# Implementation Plan: Reply Field in Message Detail Screen

We will add a reply layout in the single message details view (`MessageDetailActivity`) to allow replying directly to a contact from this screen.

## Detailed Proposed Changes

### 1. Layout (`activity_message_detail.xml`)
- Add a new horizontal `LinearLayout` for the reply input container (id `replyContainer`) immediately above the delete button (`btnDeleteDetail`).
- Include:
  - An `EditText` (`etReplyMessageDetail`) with hint `"Type a reply..."`, styled consistently with `search_bg` and text auto-correct/multi-line flags.
  - An `ImageButton` (`btnSendReplyDetail`) with standard send icon and tint.

### 2. Activity (`MessageDetailActivity.java`)
- Bind the input field `etReplyMessageDetail` and send button `btnSendReplyDetail`.
- In the `btnSendReplyDetail.setOnClickListener(...)`:
  - Extract the recipient phone number directly from `sms.getSender()`.
  - Validate that it is not null or empty.
  - Extract the message body, validate it is not empty.
  - Disable the send button, and invoke `SmsRepository.sendSms(Context, recipient, body, onSuccess, onFailure)`.
  - On success, clear the input field, re-enable the button, show a "Message sent" toast, and broadcast `REFRESH_SMS` to update the application caches/UI dynamically.
  - On failure, show a toast and re-enable the send button.
